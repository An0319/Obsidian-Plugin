# 产品规划：obsidian-smart-notes

> 更新日期：2026-09-02
> 当前版本：0.1.0（已发布，Release + Actions 全链路打通）
> 产品阶段：功能完整、价值未验证

## 一、产品定位

一句话：笔记自动归档，让用户摆脱"这篇笔记该放哪"的决策负担。

三个痛点支撑：

1. Inbox 堆积：重度用户数百上千篇笔记堆积，手动归档成本随时间增长直至放弃
2. 心流中断：写作时被迫分心思考归类
3. 现有方案取舍困境：纯规则工具无语义能力；云端 AI 付费且隐私上云

核心架构：规则 → TF-IDF 语义相似 → 本地 LLM → 社区共享配置 四级降级链，免费 + 本地优先 + 可解释。

## 二、目标用户

核心画像：笔记量 300+ 篇、使用 6 个月以上、有"收集冲动"但"整理惰性"的重度积累者。

优先切入群体（按获取难度从低到高）：

1. PKM 方法论实践者（PARA / GTD / Zettelkasten）：目录体系完整，社区活跃，种子用户最佳来源
2. 隐私敏感型用户（医生/律师/研究员/企业知识库管理）：本地 LLM 引擎是质变点
3. 中文笔记用户：bigram 分词 + 中文文档，海外竞品结构性盲区
4. 内网/无外网环境用户：Ollama 本地引擎刚需 + 团队共享规则配置

## 三、适用场景与工作流

核心场景：

1. Inbox Zero 日常归档（最高频）：新建笔记 + 网页剪藏后台自动归类
2. 历史库存清理：批量整理数百篇积压（新用户第一件事）
3. 种子库驱动归类：同类项目笔记自动跟随既有归属
4. 采集-整理流水线终端：接在 Web Clipper / QuickAdd / Templater 等采集工具下游

工作流接入：

| 工作流 | 接入方式 |
|--------|---------|
| PARA | 规则引擎路由到 Projects / Areas / Resources / Archive |
| GTD 每周回顾 | 批量整理 inbox，确认弹窗成为回顾仪式环节 |
| Zettelkasten | 文献笔记 → 永久笔记按模板/关键词分流 |
| 会议/日记流水线 | 文件名规则（日期+项目名）归入项目目录 |
| 团队知识库 | 内网 Ollama + 共享规则配置，统一归档标准 |

## 四、替代方案与竞争力

替代方案：手动整理（决策疲劳）、Smart Connections（只检索不归档）、GPT 类插件（付费+隐私+断网即瘫）、AI File Organizer 类（同前且中文弱）、不整理（最普遍的竞品）。

竞争力五支点：

1. 零边际成本：TF-IDF 纯本地计算，无 API 费用
2. 隐私红线：笔记不出本机，医疗/法律/企业场景唯一可行解
3. 降级链韧性：断网时规则 + TF-IDF 依然可用
4. 可解释 + 可控：reason 输出 + 确认弹窗 + 回滚（规划中）
5. 中文原生：分词、文档、社区三重本土化

劣势（诚实评估）：本地模型智能上限低于云端；目录体系为空时冷启动难；单人维护需积累信任。

竞争策略：不与云端 AI 拼智能上限，拼"免费 + 隐私 + 可用性下限"。护城河是反馈闭环沉淀的规则数据飞轮 + 中文社区先发位置。

战略提示：Obsidian 哲学是链接网络优先于文件夹，标签建议模式（自动打 #tags 而非移动文件）是潜在的差异化扩展方向，0.2.0 之后的候选。

## 五、0.2.0 能力扩展待办（已确认保留）

1. 反馈闭环（最高优先）：确认弹窗拒绝时可指定正确分类，自动沉淀为新规则
2. 回滚机制：整理历史记录 + 一键撤销
3. 批量整理模式：一键整理全部未归类 + 预览视图 + 批量确认
4. 治理仪表盘：整理计数、准确率、未处理池

## 六、0.2.0 关注指标清单（已确认保留）

1. 准确率度量：内置评估集（用户标注 20 篇 → 各引擎准确率报告）
2. 安全边界硬化：附件/模板目录白名单（永不触碰）；大 vault 下 TF-IDF 持久化索引
3. 冷启动引导：onboarding 流程（引导选示例笔记或导入模板库）
4. 规则可视化编辑：可视化规则构建器，降低正则门槛
5. 中文分词质量：轻量词库或 jieba 级方案替换 bigram
6. 操作舒适度：确认弹窗交互效率（键盘流、记忆上次选择）、通知不打扰写作

## 七、多语言兼容（英文场景，已确认纳入规划）

用户需求（2026-09-02）：后续需兼容英文场景。当前代码现状核查结论：

- 已支持：分词器对英文按连续字母数字段切分 + 小写化（tokenizer.ts WORD 正则），测试已覆盖英文 token
- 真实缺口三处，拆解为子项：

| 子项 | 内容 | 建议版本 | 工作量 |
|------|------|---------|--------|
| 1. TF-IDF 英文质量 | 内置英文停用词表（the/of/and 等高频词污染 IDF 权重）；轻量词干化（organize/organizing/organization 归一，后缀规则即可，无需完整 Porter） | 0.2.0（工作量最小、收益最直接） | 小 |
| 2. UI i18n | settingsTab / main / 确认弹窗 / Notice 文案当前硬编码中文，需中英双语 + 语言切换（跟随 Obsidian locale） | 0.3.0 | 中 |
| 3. LLM prompt 语言适配 | 层级三 prompt 模板需跟随笔记语言或用户设置，否则英文笔记会被建议中文分类 | 0.3.0 | 小 |
| 4. 共享配置英文规则集 | 内置规则模板当前为中文规则，需补英文模板 | 0.3.0 | 小 |
| 5. README 英文版 | 官方市场收录（obsidian-releases PR）审核前置条件 | 与市场收录节点绑定 | 小 |
| 6. manifest 核查 | 确认 description 为英文（市场审核要求） | 随 5 | 极小 |

说明：TF-IDF 层（子项 1）优先级最高，因为它是纯代码缺口且直接影响英文 vault 的分类准确率；i18n 与 README 是面向英文用户的分发前置条件。

## 八、验证路径（下一步行动）

2. 收集 10-20 个真实用户反馈
3. 按反馈实施 0.2.0 待办，优先反馈闭环与回滚（留存决定项）
4. 积累用户后向 obsidianmd/obsidian-releases 提 PR 申请官方市场收录（需声明层级三的网络请求与隐私说明）
