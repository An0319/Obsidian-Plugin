# 产品规划：Smart Notes Organizer

> 更新日期：2026-09-02
> 当前版本：0.1.0（V0.1 核心引擎已完成并发布，Release + Actions 全链路打通）
> 产品阶段：核心引擎完成、价值验证中

## 一、产品定位

**Obsidian 本地语义书签（Local Semantic Bookmark）**。

核心行为是"跟随"：用户只需把文件扔进 Inbox，点击运行，插件自动判断该文件在语义上离 Vault 中哪个文件夹最近，然后执行移动。

一句话定位：**无需联网、无需等待、永不掉线的智能归档**。

核心理念：**行为即规则（Behavior as Rule）** —— 不用配置，靠用户过往的拖拽行为自动学习。

## 二、设计哲学

1. **少即是多**：V1.0 只做一件事——把 Inbox 的文件准确地移到正确的文件夹。砍掉一切弹窗、确认框、花哨 UI。
2. **边界清晰**：终生不处理音频、图片、PDF、聊天、RAG。模块越小越可靠，能力越聚焦越可信。这是专业主义，缺陷清单本身就是产品说明书。
3. **无感体验**：用户体验是"无感"，100% 的精力砸在决策树准确率和执行速度（<100ms）上。

## 三、范围边界

### 纳入 V1.0

- 纯文本 Markdown 整理
- 四级降级链（规则映射 → TF-IDF → Ollama → 社区共享配置）
- 中文 + 英文场景
- 完全本地、零 API 费用、零数据上传

### 明确排除（终生不纳入核心）

- 音频转录、OCR、图片识别、PDF 解析
- 聊天、RAG、向量数据库
- 任何形式的云端依赖

> 此插件终生不处理音频、图片、PDF、聊天。请使用其他开源工具（如 WhisperDesktop、Tesseract）预处理为 Markdown 后，再交由本插件整理。

## 四、V1.0 功能范围（强制收缩）

### 保留

- 四级降级链（规则映射 → TF-IDF → Ollama → 社区共享配置）
- 监听 Inbox 文件夹，自动整理
- settings.ts 配置文件夹映射
- 一个 Ribbon 图标，点击即运行
- 控制台日志（Ctrl+Shift+I 查看完整决策树）

### 砍掉（不在 V1.0 内）

- 治理仪表盘（统计图表、热力图）
- 回滚机制 UI（用户应利用 Obsidian 自带的"文件恢复"核心插件）
- 批量整理确认对话框（默认全自动，无弹窗）
- 任何弹窗、确认框、花哨 UI

## 五、种子规则集（Seed Rule-set）

原"通用文件夹架构"术语废止，统一为**种子规则集**。

V1.0 只内置 3 个极简默认规则：

1. `/日志` —— 含日期格式的文件名
2. `/归档` —— 超过 30 天未修改
3. `/收件箱` —— 默认兜底

不内置任何"深度学习/法律/医学"等语义分类，这些全部交给用户的 `custom_rules.json` 去配置。

唯一的"智能"：TF-IDF 相似度匹配。用户手动把一批笔记拖进某个文件夹后，插件自动计算该文件夹的特征向量；下次再来相似内容，余弦相似度超过阈值，自动归入。

## 六、目标用户

核心画像：笔记量 300+ 篇、使用 6 个月以上、有"收集冲动"但"整理惰性"的重度积累者。

优先切入群体（按获取难度从低到高）：

1. PKM 方法论实践者（PARA / GTD / Zettelkasten）：目录体系完整，社区活跃，种子用户最佳来源
2. 隐私敏感型用户（医生/律师/研究员/企业知识库管理）：本地处理是质变点
3. 中文笔记用户：Bigram 分词 + 中文文档，海外竞品结构性盲区
4. 内网/无外网环境用户：本地引擎刚需 + 团队共享规则配置

## 七、适用场景与工作流

核心场景：

1. Inbox Zero 日常归档（最高频）：扔文件进 Inbox，点击 Ribbon 运行，自动归位
2. 历史库存清理：批量整理数百篇积压
3. 拖拽行为学习：用户整理过的文件夹自动形成特征向量，后续相似内容自动跟随
4. 采集-整理流水线终端：接在 Web Clipper / QuickAdd / Templater 等采集工具下游

工作流接入：

| 工作流 | 接入方式 |
|--------|---------|
| PARA | 规则引擎路由到 Projects / Areas / Resources / Archive |
| GTD 每周回顾 | 点击运行批量整理 Inbox |
| 会议/日记流水线 | 文件名日期规则自动归入日志目录 |
| 团队知识库 | 内网部署 + 共享规则配置，统一归档标准 |

## 八、替代方案与竞争力

替代方案：手动整理（决策疲劳）、Smart Connections（只检索不归档）、GPT 类插件（付费+隐私+断网即瘫）、AI File Organizer 类（同前且中文弱）、不整理（最普遍的竞品）。

竞争力五支点：

1. 零边际成本：TF-IDF 纯本地计算，无 API 费用
2. 隐私红线：笔记不出本机
3. 降级链韧性：断网时规则 + TF-IDF 依然可用
4. 可解释 + 可控：reason 输出 + 控制台完整决策树
5. 中文原生：Bigram 分词 + 中文文档

劣势（诚实评估）：

- 目录体系为空时冷启动困难（保留项）
- 本地模型智能上限低于云端
- 单人维护的社区插件需积累信任

竞争策略：不与云端 AI 拼智能上限，拼"免费 + 隐私 + 可用性下限"。

## 九、语言支持路线图

| 版本 | 语言支持 |
|------|----------|
| V1.0 | 中文（Bigram 分词）+ 英文（空格分词） |
| V2.0 - V3.0 | 持续优化中英文混排场景 |
| V4.0 - V5.0 | 韩语（Beta 实验性功能，需加载额外字典） |

注意：V1.0 不承诺任何韩语支持。韩语是黏着语，形态分析复杂，需单独处理。

当前代码现状：分词器已支持英文单词切分 + 小写化；V0.2 补英文停用词表与轻量词干化，直接提升英文 vault 分类准确率。

## 十、社区策略

- 不做论坛、不做 Discord
- 只通过 GitHub Issues 收集反馈，通过 PR 接受规则贡献
- 仓库内设 `/rules` 目录，存放社区贡献的 `ruleset.json`
- 社区价值在于"单向规则集市"，不在"闲聊"

## 十二、关注指标

1. 准确率度量：内置评估集（标注 20 篇 → 各引擎准确率报告）
2. 执行速度：单文件决策 + 移动 < 100ms（无感体验的硬指标）
3. 安全边界硬化：附件/模板目录白名单（永不触碰）；大 vault 下 TF-IDF 持久化索引
4. 冷启动引导：目录体系为空时的种子规则集兜底体验
5. 中文分词质量：V1.0 Bigram；V2.0-V3.0 中英混排持续优化
6. 英文质量：V0.2 停用词表 + 轻量词干化（后缀规则）

已废止的旧指标：规则可视化编辑（改为 `custom_rules.json` 路线）、操作舒适度（收敛为速度与无感指标）。

## 十三、验证路径

1. 真机验证（阻塞项，需用户执行）：Release 下载 main.js + manifest.json + styles.css 放入 .obsidian/plugins/obsidian-smart-notes/ 启用，重点验证降级链、种子规则集、Inbox 监听、链接更新、Ollama 连通
2. 通过 GitHub Issues 收集真实用户反馈
3. V0.2：custom_rules.json + 英文停用词/词干化
4. V0.3：上架 Obsidian 社区插件市场（README 英文版、manifest 英文 description 为审核前置条件）
